Behaviors and acceptance criteria

Upload and reading files
  • One master (~500 rows) and one Amazon template per run; rules sheet and data sheet(s) are read.
Column mapping
  • AI proposes; user confirms or changes each pair. Most values come straight from the master.
  • [ ] Every template column shows a proposed master column or "not mapped"
  • [ ] User can change any pair before moving on
Asking about missing columns
  • One column at a time; dropdown columns force an allowed value; skipping is allowed.
  • [ ] Only one question visible at a time, with progress
  • [ ] Dropdown shows exactly the template's allowed values
  • [ ] Invalid answer is rejected with the reason
  • [ ] Skip moves to the next column
Validation and QC
  • Every row checked against the rules; skipped mandatory columns flagged.
  • [ ] Summary lists each problem with column and row count
  • [ ] No problems shown when all mandatory columns are filled and valid
Output
  • [ ] Downloaded file opens in Excel as the same VBA-enabled template with rows filled
  • [ ] All mandatory columns filled for all rows

States and boundaries

Before uploadTwo empty boxes; start button disabled until both files are added.
Skipped mandatory columnAllowed, flagged at validation with a prompt to fill it.
Invalid answerRejected with the reason; the same question stays on screen.
Unusable file (assumption)Clear error, upload again.
Nothing persists (assumption)Closing the page loses progress.

Deferred, non-goals, open questions

Deferred from the POCOther marketplaces; saving mappings across runs; marketplace's own validator check; accounts and deployment.
Non-goalsEditing the template's VBA code; non-Amazon output.
Open questions
  • How does the user supply values that differ per product/variant? (Assumed: from a master column, or entered for a group of rows such as by CATEGORY.) Must be settled before the spec.
  • Confirm or change the two assumptions above.
